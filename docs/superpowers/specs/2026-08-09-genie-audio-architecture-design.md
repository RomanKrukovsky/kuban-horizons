# Аудиоархитектура Кубанской джиннии

Дата: 2026-08-09
Статус: спека утверждена, реализация не начата

## Задача

У джиннии ~130 классов механик, ~70 мест с частицами и **один** звук —
`entity/genie/snap.ogg`. Он играется с `1.0F, 1.0F` во всех десяти точках
вызова, поэтому «сменилось настроение NPC» и «переписана реальность» звучат
одинаково. Полный production-пакет — около **222 события**, из них ~20 петель.

Главная инженерная задача — **не сократить количество звуков, а сделать
добавление сотен звуков дешёвым и data-driven**. Сейчас один звук требует пяти
правок в четырёх файлах:

1. `registry/KHSounds.java` — регистрация `SoundEvent`;
2. `datagen/KHSoundDefinitionsProvider.java` — определение для `sounds.json`;
3. `datagen/KHTranslations.java` — ключ субтитра с en/ru;
4. `.ogg` на диске;
5. точка вызова в коде механики.

На 222 события это ~884 ручные правки. `tools/soundgen/check_sounds.py`
существует именно потому, что этот класс ошибок уже случался дважды (19
голосов фауны без файлов; щелчок джиннии в `sounds.json` и в коде при
отсутствии файла) — но он лишь **проверяет** согласованность трёх рукописных
источников постфактум, и в CI не запускается.

Цель: один звук = **одна запись** в манифесте. Остальное генерируется.

## Границы

В объёме: SFX-архитектура (манифест, codegen, DSP-модули, клиентские hooks,
тесты), полная карта звуков по существующим механикам `genie/`, наполнение
библиотеки итерациями до production-объёма.

Вне объёма: **голосовые реплики**. Голос отложен целиком отдельным проектом;
`GenieLanguageModel` продолжает отдавать текст. Никакой инфраструктуры под
речь эта спека не создаёт.

## Аудиологотип: четыре материала

Идентичность строится на четырёх материалах, из сочетаний которых собираются
все способности. Это ограничение синтеза, а не список ассетов: узнаваемость
даёт повторение материала, а не количество файлов.

| Модуль | Физическая модель | Полоса |
|---|---|---|
| `TailAirSynth` | воздух/дым: турбулентность + медленная АМ, без тонального ядра | 200 Гц – 6 кГц |
| `GoldMaterialSynth` | золото: негармоничные моды металла + транзиент контакта; вариации по массе (браслет / цепочка / подвеска) | 400 Гц – 9 кГц |
| `SapphireChimeSynth` | сапфировый звон: чистое ядро + длинный затухающий хвост, малая расстройка партиалов | 1.2 – 8 кГц |
| `LowWarmResonanceSynth` | низкий тёплый магический резонанс: вес в **80–200 Гц**, саб-слой опционален | 40 – 400 Гц |

Производный модуль: `ImpactShieldSynth` — золото + сапфир, для шести типов
урона по оболочке.

### Тембр и ART_BIBLE

ART_BIBLE §6 требует «без резких синтетических тембров». Это **не конфликтует**
с процедурной генерацией: способ создания и характер тембра — разные вещи.
Существующий `wood_creak` в `generate_press_sounds.py` — физическая модель
трения (stick-slip зерно из затухающих резонансов, band-limited пила,
медленное дрожание ±18 Гц), то есть органика, сделанная numpy. Правка
ART_BIBLE не требуется; требование к характеру звука сохраняется в силе.

### Бас

Основной перцептивный вес — **80–200 Гц**. Саб-бас ниже ~60 Гц добавляется
только дополнительным слоем: на ноутбучных динамиках его нет, и звук,
построенный только на нём, у половины игроков превратится в тишину — особенно
обидно после специально сделанной паузы (§ «тишина как сила»).

## Возможности движка (проверено по исходникам MC 26.2)

Три вопроса были исследованы по распакованным `minecraft-patched-26.2.0.48-beta-sources.jar`
и jar'ам LWJGL/NeoForge, а не по предположениям.

### Подвижные эмиттеры — доступны

`SoundEngine.tickInGameSound()` каждый тик перечитывает `getX/getY/getZ` и
пишет позицию в `AL_POSITION`, но **только для `TickableSoundInstance`**;
обычный `SoundInstance` фиксирует позицию однократно при старте.

Пул каналов делится на static/streaming: static — **247** на типичном
устройстве (**25** в худшем случае при fallback), streaming — **8 на всю игру**.
Хвост идёт через static (`"stream": false`).

Два ограничения, влияющие на дизайн:

- позиции эмиттеров обновляются на **20 Гц** без интерполяции, слушатель —
  покадрово. Быстрый хвост будет шагать рывками по 50 мс, поэтому позиции
  **демпфируются** (экспоненциальное сглаживание), а не берутся сырыми;
- `AL_VELOCITY` движок не задаёт вообще — Doppler отсутствует, бесплатного
  ощущения движения не будет.

Несколько близких эмиттеров суммируются примерно как ×√N при линейном
затухании с `refDistance = 0` (усиление 1.0 у источника), поэтому громкость
на эмиттер делится на √N, а сами эмиттеры декоррелируются (разный питч,
разные варианты файла).

### EFX-реверб — доступен, нужен один AT

LWJGL 3.4.1 везёт **OpenAL Soft 1.25.1** (не устаревший фреймворк Apple).
В нативе есть настоящий DSP-реверб: `ReverbState`, 23 константы
`AL_EAXREVERB_*`, диагностика диапазонов. Ванилла EFX **не использует** —
ноль вызовов в `net/minecraft/client/sounds/` и `com/mojang/blaze3d/audio/`,
слоты полностью свободны.

NeoForge отдаёт `PlaySoundSourceEvent` / `PlayStreamingSourceEvent` с
публичными `getSound()` и `getChannel()` — связка «`SoundInstance` → канал»
есть из коробки, mixin для неё не нужен. `SoundEngineLoadEvent` — точка
инициализации, срабатывает и при смене устройства.

Требуется **ровно один access transformer** на одно поле:

```
public com.mojang.blaze3d.audio.Channel source
```

`Channel.source` — `private final int` без геттера, не менялся с 1.20.1. AT
предпочтён mixin'у: падает громко при загрузке, а не тихо в рантайме.

Ограничение: aux sends по умолчанию **2**, не 4 (`DefaultSendCount = 2`;
4 только на Windows с legacy EAX, 6 — жёсткий максимум). Расширение требует
патча `Library.createAttributes` — именно того mixin'а, из-за которого у
Sound Physics Remastered ломался HRTF. Поэтому проектируем на **1–2 слота**,
`Library` не патчим, `ALC_MAX_AUXILIARY_SENDS` читаем в рантайме и деградируем.

Вывод: **динамический реверб под размер джиннии возможен**.

### Жёсткие ограничения

- **Спатиализуется только моно.** Спека OpenAL 1.1: буферы с более чем одним
  каналом играются без 3D. `JOrbisAudioStream` берёт формат из заголовка Ogg,
  стерео никто не конвертирует и не отсекает — стерео-файл молча теряет и
  затухание, и реверб. Все позиционные звуки — строго моно.
- **Питч зажат `[0.5, 2.0]`** в `SoundEngine.calculatePitch()`
  (`Mth.clamp(pitch, 0.5F, 2.0F)`), на обоих путях — и при старте, и каждый
  тик. Клиентский `SoundInstance` обхода **не даёт**. Сеть тут не виновата:
  в `ClientboundSoundPacket` питч передаётся полным float. Вес голоса гиганта
  набирается сменой файла и EFX, а не питчем.
- Рантайм-синтез PCM возможен (NeoForge добавил `SoundInstance.getStream`),
  но только для streaming-звуков — 8 каналов на игру и ~4 с буферизации.
  Годится для дронов, не для реактивных звуков; со хвостом на static-пуле
  взаимоисключающе. В первой версии не используется.

## Архитектура

### Манифест как единственный источник

Рассмотрены три варианта.

**A. JSON-манифест + рантайм-регистрация.** Java читает манифест при
инициализации и регистрирует всё циклом. Отклонён: теряется compile-time
проверка, `KHSounds.GENIE_SNAP` превращается в строковый лукап, и на 222
события опечатка находится только в запущенной игре.

**B. JSON-манифест + codegen Java-холдеров.** Выбран. Манифест — источник
истины, генератор пишет Java-файл с заголовком «СГЕНЕРИРОВАНО». Авторская
работа — одна запись, компилятор по-прежнему ловит опечатки в точках вызова.
Прецедент в проекте есть: `src/generated/resources`.

**C. Манифест таблицей на Java + итерация в провайдерах.** Отклонён: Python не
может прочитать Java без парсинга, а DSP-рецепты должны жить рядом с
определением звука.

Расположение артефактов:

- манифест — `tools/soundgen/manifest/genie.json` (данные, правится вручную);
- DSP-модули материалов — `tools/soundgen/synth/` (`tail_air.py`, `gold.py`,
  `sapphire.py`, `low_resonance.py`, `impact_shield.py`), общие примитивы
  переиспользуются из `generate_press_sounds.py`;
- генератор — `tools/soundgen/build_genie_audio.py` (читает манифест, пишет
  `.ogg` и Java-холдеры);
- сгенерированные Java-холдеры — `registry/KHGenieSounds.java` с заголовком
  «СГЕНЕРИРОВАНО, не править руками»;
- карта звуков по механикам — `docs/dev/genie-audio-map.md`, сверяется тестом
  покрытия.

Одна запись манифеста содержит:

- идентификатор события (`entity.genie.<...>`);
- путь файла и число вариантов;
- subtitle-ключ + текст en/ru;
- категорию (`SoundSource`), stream/static, петля или нет;
- DSP-рецепт: список материалов с весами и параметрами;
- ссылку на точку вызова (класс + механика) — для проверки покрытия.

### Что генерируется

Из одной записи:

1. регистрация `SoundEvent` (Java-холдеры, сгенерированный файл);
2. определения для `sounds.json`: генератор пишет
   `KHGenieSoundDefinitions` с перечислением записей, которое
   `KHSoundDefinitionsProvider` вызывает одной строкой — существующие
   определения фауны и пресса не трогаются;
3. subtitle-ключи в обеих локалях: генератор пишет отдельный класс
   `KHGenieSoundTranslations` со своим статическим блоком, который вызывается
   из `KHTranslations` одной строкой. Рукописный реестр строк не перезаписывается,
   а расширяется — дубликаты по-прежнему падают по построению;
4. варианты `.ogg` из DSP-рецепта;
5. метаданные для валидации.

Ни один из четырёх файлов не правится руками. Соглашения синтеза наследуются
от `generate_press_sounds.py`: фиксированный SEED, 44.1 кГц, моно, пик
−3 dBFS, fade 12 мс, кодирование через `soundfile`.

Существующие 46 событий (фауна, пресс, амбиент) **остаются в `KHSounds.java`
без изменений** — миграция их на манифест в объём не входит. Новый
`KHGenieSounds` регистрируется в том же реестре рядом; оба класса
сосуществуют, и `check_sounds.py` проверяет оба. Так масштабная перестройка не
затрагивает уже работающий и покрытый проверками звук.

`KHTranslations` уже реализует эту же идею для строк — единый источник, обе
локали, дубликат ключа падает по построению. Звук получает такой же контракт.

### Клиентский слой

- **Хвост**: 3–5 `TickableSoundInstance` на static-пуле, позиции
  демпфируются, громкость на эмиттер делится на √N, декорреляция вариантами
  и питчем в пределах `[0.5, 2.0]`.
- **EFX**: отдельный слой поверх. Инициализация на `SoundEngineLoadEvent`,
  гейт по `ALC_EXT_EFX`, чтение `ALC_MAX_AUXILIARY_SENDS` с деградацией,
  удаление слотов/эффектов при пересоздании контекста. Если EFX недоступен —
  звуки играют **без реверба**, а не пропадают.
- Все AL-вызовы выполняются на потоке звукового движка: `PlaySoundSourceEvent`
  постится изнутри `handle.execute(...)`, то есть уже на нужном потоке.
  Обращения из тикового кода маршрутизируются через executor движка.

### Побочный фикс

`KHAmbienceVolume.Scaled` реализует `SoundInstance`, а не
`TickableSoundInstance`. При обёртывании петли биома
(`BiomeAmbientSoundsHandler.LoopSoundInstance` — это
`AbstractTickableSoundInstance`) обёртка **срезает тикабельность**: движок
перестаёт вызывать `tick()`, и фейды, которые javadoc обещает сохранить, не
работают. Исправляется в том же проходе — обёртки эмиттеров опираются на тот
же механизм и обязаны форвардить `tick()`/`isStopped()`.

## Карта звуков

Полная карта строится по существующим механикам `genie/` (~130 файлов).
Приоритет — механики, у которых **уже есть частицы, но нет звука**: частица
маркирует точное место, где звук должен быть.

Области покрытия: движение и хвост (5 состояний `GenieTailState` + переходы +
дымовое кресло); аура и близость (6 темпераментов, аура законов, резонанс
степи); украшения (вероятностный слой 20–35 %, иначе звон начинает бесить);
щелчок (тиры вместо одного плоского звука); телепорт с раздельными уходом и
приходом; желания по мощности и типу; reality warp; рост и уменьшение;
6 типов урона по оболочке; появление из сосуда (5 `VesselKind`); эмоции и
idle; сны; прогрессия, трансформация и концовки.

Отдельно фиксируются самые дешёвые точки подключения: шесть методов
`playGreet` / `playWish` / `playCast` / `playSpawn` / `playDespawn` /
`playHurt` в `KubanGenie` сейчас вызывают только `triggerAnim` без единого
`SoundEvent`.

Неуязвимость уже различает шесть типов урона (меч/топор, снаряд, sonic boom,
взрыв, `/kill`+бездна, прочее) — шесть разных звуков оболочки оправданы
существующим кодом, а не придуманы.

Учитываются мёртвые ветки (недостижимые состояния и движки без вызывающих):
звук для них не производится, пока механика не подключена.

## Тесты

- `check_sounds.py` переориентируется с проверки трёх рукописных источников
  на проверку «манифест ↔ сгенерированное»;
- добавляется валидация формата: моно, 44.1 кГц, непустой файл, пик в
  допуске, отсутствие стерео среди позиционных звуков;
- проверка покрытия: каждая механика из карты имеет привязку либо явную
  отметку «звука не требует»;
- тест детерминированности синтеза: повторный запуск даёт те же файлы;
- **запуск в CI** — сейчас `check_sounds.py` в workflow отсутствует.

## Порядок работ

1. Инфраструктура: манифест, codegen, DSP-модули четырёх материалов, hooks,
   тесты, CI.
2. **16 звуков** — сквозная проверка инфраструктуры: одна запись манифеста
   действительно даёт регистрацию, определение, субтитр, файл и звук в игре.
3. Наполнение до production-объёма итерациями по карте механик.

Пункт 2 — тест инфраструктуры, **не** конечный scope. Конечный объём —
полный аудиопакет персонажа.

## Риски

- **Версионная хрупкость**: `Channel.source` стабилен с 1.20.1, но AT на
  приватное поле остаётся зависимостью от внутренностей. Падает при загрузке,
  а не тихо. NeoForge 26.2.0.48-beta — бета новой версии.
- **Драйверы**: EFX проверен на macOS arm64 по факту запуска. Гейт по
  расширению обязателен, поведение при отсутствии — деградация без реверба.
- **Стерео-ассеты** молча теряют пространственность: ловится валидацией
  формата.
- **20 Гц эмиттеров** может быть слышно как рывки на быстром хвосте:
  проверяется на слух после первого прохода, лечится демпфированием.
- **Суммирование громкости** близких эмиттеров: делитель √N — начальное
  значение, требует проверки ушами.
- **Утечки при смене устройства**: слоты/эффекты/фильтры удаляются явно при
  пересоздании контекста.
