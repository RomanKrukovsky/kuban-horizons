# Карманное измерение джиннии — «Вечная Кубань» (срез 1)

Дата: 2026-08-09 · Ветка: `gauntlet/full-production` · Эпик: Pocket Space
(GENIE_VISION эпик 6) · Этап ROADMAP: 13

## 1. Цель

Зарегистрировать первое настоящее измерение мода и дать игроку рабочий вход в
него через магический сосуд. Это закрывает пункт концепта «Карманное измерение
внутри лампы» в минимальном, но полностью честном объёме и снимает главный
структурный блокер: аудит показал, что **ни одного кастомного измерения в моде
нет**, поэтому все «карманные миры» концепта до сих пор были иллюзией.

### В объёме

- измерение `kubanhorizons:eternal_kuban` с ландшафтом из четырёх готовых биомов;
- законы измерения, выражаемые декларативно: вечный закат, отсутствие погоды,
  запрет враждебных мобов;
- предмет-сосуд `genie_lamp`: вход и выход;
- сохранение точки входа между сессиями и после потери сосуда;
- локализация ru+en, модель, текстура, рецепт, лут, теги;
- GameTest и unit-тесты.

### Вне объёма (следующие срезы, перечислено чтобы не расползалось)

- дворец и его материализация «по щелчку»;
- гравитация 30% и полёт гостей;
- школы разных сосудов (`VesselKind` остаётся неиспользованным);
- архив желаний, картины, зеркальный мир;
- неевклидова геометрия и рекурсия сосудов;
- настраиваемые игроком законы измерения через `PolicyService`.

## 2. Проверенные факты, на которых стоит дизайн

Установлено чтением кода, а не по памяти:

1. **Измерения регистрируются datapack-JSON**, поэтому измерение появится в любом
   мире, включая существующие сейвы, и не требует opt-in пресета. Биомы мода,
   наоборот, живут только внутри `KHWorldPresets.KUBAN_HORIZONS`
   (`KHWorldPresets.java:63-66`) — это разные механизмы, и здесь это преимущество.
2. **`Registries.DIMENSION_TYPE` и `Registries.LEVEL_STEM` в датагене
   отсутствуют.** `KHDataGen` регистрирует 11 реестров (`KHDataGen.java:19-39`),
   ни одного из этих двух. Их нужно добавить.
3. **Поводок уже работает кросс-дименсионно.** `GenieLeash.keepNear`
   (`GenieLeash.java:92-103`) сравнивает `genie.level().dimension()` с
   измерением игрока и телепортирует через `TeleportTransition`, а `restoreFrom`
   переносит UUID. Следовательно **джинния последует за игроком внутрь без новой
   логики** — это надо только покрыть тестом, а не писать.
4. **Якорь уникальности лежит в оверворлде.** `GenieAnchor.memory()` всегда берёт
   `WorldGenieMemory.get(server.overworld())` (`GenieAnchor.java:31`), причём
   комментарий прямо объясняет: иначе переход в другое измерение позволил бы
   завести вторую джиннию. Новое измерение обязано сохранить это свойство.
5. **`FinalizeSpawnEvent` уже используется** (`KHEntityEvents.java:74`) — есть
   готовый прецедент управления спавном, отдельный механизм не нужен.
6. **`TeleportTransition` — актуальный API 26.2** для смены измерения, уже
   применяется в проекте.
7. **`KubanBiomeSource` пригоден для кармана без изменений.** Это тонкая проекция
   поверх ванильного multi-noise пресета: swamp → плавни, mangrove_swamp → лиман,
   river → пойма, всё остальное → степь (`KubanBiomeSource.java:61-73`).
   Привязки к оверворлду нет — список параметров передаётся в конструктор
   (`:40`), поэтому тот же класс переиспользуется как есть.

## 3. Архитектура

Новый пакет `worldgen/dimension/`, потому что это worldgen, а не магия джиннии;
пакет `genie/dimension/` остаётся за игровой логикой.

### 3.1 `KHDimensions`

Ключи и bootstrap:

- `ResourceKey<DimensionType> ETERNAL_KUBAN_TYPE`
- `ResourceKey<Level> ETERNAL_KUBAN` (для телепорта)
- `ResourceKey<LevelStem> ETERNAL_KUBAN_STEM`

`DimensionType` (все значения — осознанные решения, не копия оверворлда):

| Параметр | Значение | Почему |
|---|---|---|
| `fixedTime` | `6000` | вечный закат из концепта, декларативно |
| `hasSkylight` | `true` | ландшафт должен освещаться |
| `hasCeiling` | `false` | это степь, не Нижний мир |
| `natural` | `false` | запрещает порталы Нижнего мира и компас внутри |
| `coordinateScale` | `1.0` | не связано с оверворлдом координатно |
| `bedWorks` | `false` | сон здесь не имеет смысла при фиксированном времени |
| `respawnAnchorWorks` | `false` | точка возврата — точка входа, см. 3.3 |
| `minY` / `height` | `-64` / `384` | как оверворлд, чтобы биомы генерировались штатно |
| `piglinSafe` | `false` | нет пиглинов |
| `ultraWarm` | `false` | вода не испаряется |
| `monsterSpawnLightTest` / `monsterSpawnBlockLightLimit` | `0` | враждебных мобов нет по правилу 3.4 |

`LevelStem`: `NoiseBasedChunkGenerator` + `KubanBiomeSource` с четырьмя биомами
(`KHBiomes.KUBAN_STEPPE`, `PLAVNI`, `LIMAN`, `RIVER_FLOODPLAIN`) и
`KHNoiseSettings.OVERWORLD` — переиспользуется существующий рельеф. Класс
`KubanBiomeSource` берётся без правок (см. факт 7), ему передаётся
`MultiNoiseBiomeSourceParameterLists.OVERWORLD` как источник климата.

Погода отключается не в `DimensionType` (там такого поля нет), а правилом 3.4.

### 3.2 Датаген

`KHDataGen` дополняется двумя реестрами:

```
.add(Registries.DIMENSION_TYPE, KHDimensions::bootstrapType)
.add(Registries.LEVEL_STEM, KHDimensions::bootstrapStem)
```

Сгенерированный JSON коммитится (AD-005).

### 3.3 Сосуд `genie_lamp`

Предмет, а не блок: концепт требует «снаружи обычная маленькая лампа».
Геометрия и текстура переиспользуют готовые `kuban_jug.geo.json` /
`kuban_jug.png` — новых ассетов рисовать не нужно.

- ПКМ снаружи → телепорт в `ETERNAL_KUBAN`;
- ПКМ внутри → возврат **в точку входа**.

**Точка входа хранится в player attachment, не в компоненте предмета.**
Обоснование: концепт устанавливает железное правило «Разрушение сосуда не
убивает её» — по той же логике потеря сосуда не должна замуровывать игрока
внутри. Компонент предмета исчезает вместе с лампой в лаве; attachment — нет.
Формат — как у `ChunkFertilityData` и путеводителя: `ValueIOSerializable` +
`SchemaVersion`, перенос после смерти.

Запись: `ResourceKey<Level>` исходного измерения + `Vec3` позиции + `yRot`.

### 3.4 Законы измерения

- **Враждебные мобы запрещены.** Расширяется существующий обработчик
  `FinalizeSpawnEvent` (`KHEntityEvents.java:74`): в `ETERNAL_KUBAN` спавн
  сущностей категории `MONSTER` отменяется. Это покрывает и естественный спавн,
  и спавнеры.
- **Погоды нет.** На входе в измерение и на server tick для этого уровня
  дождь/гроза сбрасываются. Реализуется как явная проверка уровня, без
  глобальных gamerule — иначе затронет оверворлд.
- **Время не течёт** — обеспечивается `fixedTime`, кода не требует.

### 3.5 Границы безопасности

- **Транзакционный рантайм не пересекает измерения.** `RegionSelection` привязан
  к одному уровню; добавляется явный тест, что снимок, сделанный в оверворлде,
  нельзя восстановить в `ETERNAL_KUBAN`. Это защищает уже готовый Wish Runtime
  от появления кросс-дименсионной дыры.
- **Уникальность джиннии не меняется.** `GenieAnchor` не трогается; тест
  подтверждает, что после перехода в карман джинния остаётся одна.
- **Выход при отсутствии измерения.** Если игрок сохранился внутри, а `LevelStem`
  недоступен, respawn уводит в оверворлд по сохранённой точке входа, а не в void.

## 4. Тесты

GameTest (регистрация в `KHGameTests` по существующей схеме 26.2):

1. `pocket_dimension_exists` — `ETERNAL_KUBAN` присутствует у сервера и
   генерирует непустой чанк.
2. `pocket_vessel_enters` — ПКМ лампой переносит игрока в `ETERNAL_KUBAN`.
3. `pocket_vessel_returns_to_entry` — выход возвращает именно в точку входа, а не
   на мировой спавн.
4. `pocket_forbids_hostiles` — попытка спавна `MONSTER` внутри отменяется.
5. `pocket_time_is_fixed` — время суток не изменяется после тиков.
6. `pocket_keeps_genie_unique` — после перехода `GenieAnchor.find` возвращает ту
   же одну джиннию.
7. `pocket_genie_follows_owner` — поводок переносит джиннию за хозяином внутрь
   (проверка уже существующего поведения).
8. `pocket_snapshot_is_dimension_scoped` — восстановление снимка из другого
   измерения отклоняется.

Unit: сериализация точки входа, включая миграцию схемы и отсутствующую запись.

Каждый тест обязан падать по существу: проверяется наблюдаемое состояние мира, а
не «сущность жива после вызова void-метода». Аудит показал такой антипаттерн в
`KHGameTests.java:579-586` — здесь он не повторяется.

## 5. Критерий готовности

Согласно чек-листу `AGENTS.md`: код, модель, текстура, локализация ru+en,
рецепт, лут, теги, тесты, `./gradlew compileJava` и `runGameTestServer` зелёные,
обновлённые `PROJECT_STATE.md`, `ROADMAP.md` (этап 13) и матрица в
`GENIE_VISION.md` — пункт «Измерения» переходит из «спроектировано» в «готово»
**только** для входа и законов, с явной пометкой, что дворец не входит.

Заглушек не добавляется. Ни один класс не создаётся без вызывающей стороны —
это прямое следствие аудита, нашедшего семь классов с нулём вызовов.

## 6. Риски

| Риск | Мера |
|---|---|
| Размер сейва: новый уровень генерирует чанки | измерение посещается редко; при необходимости ограничить радиус позже, но не в этом срезе |
| Существующие сейвы | измерение добавляется через datapack и появляется при загрузке; миграция не требуется, но нужен smoke-тест на старом мире |
| Вечный закат + `bedWorks=false` мешает игроку спать | ожидаемое поведение измерения, отражено в локализации подсказкой |
