# GUI взаимодействия с Кубанской джиннией

Дата: 2026-08-09

## 1. Задача

При правом клике по джиннии без предмета в руке игрок получает три
системных сообщения подряд:

```
Характер: гордая | доверие 100, уважение 95, страх 0, симпатия 80,
свобода 80, могущество 10, искажение 0. Переименуйте бумагу в желание...
Разум: следовать | спасений 2, отражено угроз 174, остановлено снарядов 6...
Память мира: исполнено желаний 0, совершено спасений 3, защищено поселений 0.
```

Семь чисел в одну строку глаз не читает. Данные тонут в общем потоке чата,
исчезают при прокрутке и не обновляются: чтобы увидеть новое доверие, надо
кликать заново.

Смена режима поведения не лучше: `Shift`+ПКМ перебирает четыре режима по
кругу (`GenieBrain.cycleMode`), результат виден только в чате. Чтобы попасть
из `FOLLOW` в `SCOUT`, нужно кликнуть трижды и следить за строкой.

Желание требует переименовать бумагу в наковальне и применить её на джиннию.

Задача — заменить это экраном: шкалы вместо чисел, кнопки вместо цикла,
поле ввода вместо наковальни.

## 2. Диагноз существующего поведения

`KubanGenie.mobInteract` (строки 381–397) заканчивается тремя вызовами
`player.sendSystemMessage`. Данные берутся из трёх источников:

- `GeniePersonality` — семь шкал (`trust`, `respect`, `fear`, `affection`,
  `freedomDrive`, `power`, `corruption`) и производный `temperament()`;
- `GenieBrain` — режим (`mode()`) и четыре счётчика (`rescues`,
  `threatsRepelled`, `projectilesIntercepted`, `wishesObserved`);
- `WorldGenieMemory` — три счётчика мира (`totalWishesGranted`,
  `totalRescuesPerformed`, `savedVillagesCount`).

Все значения — `int`, что делает их пригодными для `ContainerData`.

Желание проходит путь: переименованная бумага → `WishParser.parse(String)` →
`personality.observeWording` → `WishExecutor.execute` → сообщение в чат.
Парсер принимает обычную строку, поэтому источник текста не важен — бумага
нужна только как носитель.

В моде есть рабочий образец GUI: `OilPressMenu` + `OilPressScreen` +
`KHMenus`. Сетевого слоя (`CustomPacketPayload`) нет ни одного.

## 3. Решение

`AbstractContainerMenu` со синхронизацией через `ContainerData` — тот же
механизм, что гоняет прогресс маслопресса. Числа обновляются живо силами
ванильной синхронизации, свой протокол для них не нужен.

`ContainerData` передаёт только `int`, поэтому строка желания и выбор режима
идут отдельными пакетами. Это первый сетевой слой в моде; он же понадобится
для голосового ввода в будущем.

### 3.1 Компоновка экрана

Окно 176×200, слотов инвентаря нет — предметы в этом экране не участвуют.

```
┌────────────────────────────────────────┐
│  Кубанская джинния            [гордая] │
├────────────────────────────────────────┤
│  Доверие      ███████████████░░░  100  │
│  Уважение     ██████████████░░░░   95  │
│  Страх        ░░░░░░░░░░░░░░░░░░    0  │
│  Симпатия     ████████████░░░░░░   80  │
│  Свобода      ████████████░░░░░░   80  │
│  Могущество   █░░░░░░░░░░░░░░░░░   10  │
│  Искажение    ░░░░░░░░░░░░░░░░░░    0  │
├────────────────────────────────────────┤
│  Режим:  [Следовать] Ждать Охрана Дозор│
├────────────────────────────────────────┤
│  Спасений 2 · угроз 174 · желаний 0    │
│  Мир: желаний 0 · спасений 3 · сёл 0   │
├────────────────────────────────────────┤
│  Желание: [________________________]   │
│                            [ Просить ] │
└────────────────────────────────────────┘
```

Решения по компоновке:

- **Шкалы, а не числа.** Полоса даёт соотношение мгновенно; число рядом
  остаётся для точности. Цвет несёт смысл: доверие и симпатия зелёные,
  страх красный, искажение фиолетовое, остальные нейтральные.
- **Четыре кнопки режима, а не цикл.** Видны все варианты и текущий.
- **Статистика строкой.** Это счётчики без максимума (174 угрозы), шкала для
  них бессмысленна.
- **Поле ввода внизу.** Место, куда позже встанет кнопка микрофона: голос
  станет вторым источником той же строки.

### 3.2 Компоненты

| Файл | Назначение |
|---|---|
| `menu/GenieMenu.java` | `AbstractContainerMenu` без слотов, `ContainerData` на 15 int |
| `client/screen/GenieScreen.java` | Отрисовка: шкалы, кнопки, `EditBox` |
| `network/SetGenieModePayload.java` | Клиент→сервер: `entityId`, ordinal режима |
| `network/GenieWishPayload.java` | Клиент→сервер: `entityId`, текст желания |
| `registry/KHNetwork.java` | Регистрация пакетов на `RegisterPayloadHandlersEvent` |

Правки существующих файлов:

- `KubanGenie.mobInteract` — три `sendSystemMessage` заменяются на
  `player.openMenu(...)`;
- `GenieBrain` — добавляется `setMode(GenieBehaviorMode)`; `cycleMode()`
  остаётся, его использует `Shift`+ПКМ;
- `KHMenus` — регистрация `GENIE`;
- `KHTranslations` — строки экрана (ru + en);
- `tools/texgen/gen_gui.py` — генерация текстуры панели.

## 4. Поток данных

**Открытие.** ПКМ без предмета → сервер проверяет владельца → `openMenu`
с провайдером, передающим `entityId` джиннии в буфер. Клиент строит меню и
знает, к какой джиннии привязан.

**Обновление чисел.** Сервер каждый тик пишет 15 значений в `ContainerData`;
ванилла шлёт только изменившиеся. Шкалы двигаются сами.

**Смена режима.** Клик по кнопке → `SetGenieModePayload` → сервер проверяет
владельца и дистанцию → `brain.setMode(...)`. Реплика в чат сохраняется.

**Желание.** `Enter` или кнопка «Просить» → `GenieWishPayload` → сервер
проверяет владельца, дистанцию и длину → `WishParser.parse` →
`observeWording` → `WishExecutor.execute` → ответ в чат.

**Закрытие.** `stillValid()` возвращает false, если джинния мертва или
игрок дальше 8 блоков; окно закрывается силами ванилы.

## 5. Что остаётся в чате

Цифры полностью уходят в GUI. В чате остаются только реплики джиннии как
живой героини — они несут характер, а не данные:

- ответы на желания («Вы просили алмазы. Где именно — не сказали»);
- предупреждения искажённых желаний;
- привязка, отказ не-владельцу, смена режима;
- шёпот блоков и прочая атмосферная речь.

Три статусных сообщения (`genie.status`, `genie.ai.status`,
`genie.memory.status`) больше не отправляются. Ключи переводов остаются в
`KHTranslations`: они используются в `KHGameTests`, и удаление сломало бы
тесты без пользы.

## 6. Безопасность

Сервер не доверяет клиенту ни в чём. Каждый пакет проверяет:

1. `entityId` указывает на существующую сущность класса `KubanGenie`;
2. отправитель — владелец **этой** джиннии (`isOwnedBy`);
3. дистанция до джиннии ≤ 8 блоков;
4. для желания: длина текста ≤ 256 символов, иначе обрезается.

Нарушение любого пункта — молчаливый игнор. Ответ об ошибке не отправляется:
он подтвердил бы существование и состояние чужой джиннии.

Клиентские проверки (неактивная кнопка при пустом поле, лимит `EditBox`)
существуют для удобства; решение всегда за сервером.

## 7. Крайние случаи

| Ситуация | Поведение |
|---|---|
| Джинния умерла при открытом окне | `stillValid()` → false, окно закрывается |
| Игрок отошёл дальше 8 блоков | То же |
| Пакет от не-владельца | Молчаливый игнор |
| `entityId` указывает не на джиннию | Молчаливый игнор |
| Пустое поле желания | Кнопка неактивна, пакет не уходит |
| Текст длиннее 256 символов | Обрезается на сервере |
| `WishParser` не понял текст | Существующее поведение: `wish.unknown` в чат |
| Владелец ещё не назначен | Существующее поведение: привязка + приветствие, окно не открывается |
| Не тот игрок | Существующее поведение: `not_owner` в чат |

## 8. Осознанные решения по балансу

**Желания бесплатны и без кулдауна.** Бумага была единственной ценой
желания: ни кулдауна, ни лимита в коде нет. Убрав бумагу, мы убираем цену
целиком — игрок может запрашивать сундук алмазов сколько угодно. Владелец
проекта выбрал это сознательно; троттлинг не добавляется.

**Искажённые желания не требуют подтверждения.** Фразы вида «хочу быть
всемогущим» запускают необратимую трансформацию игрока в джиннию
(`DistortedWishEngine` → `PlayerGenieTransformationController`). С бумагой
это требовало усилий; в поле ввода набирается за секунды. Диалог
подтверждения было предложено добавить и сознательно отклонено.

**Смена режима без троттлинга.** Спам-клик меняет одно поле, вреда нет.

## 9. Голосовой ввод (не в этой работе)

Голос обсуждался и отложен: в моде нет ни распознавания речи, ни
зависимостей для него (единственная зависимость — GeckoLib). Локальная
модель (Vosk/Whisper) — отдельный проект: весомая зависимость, модель на
диске, разрешения ОС, работа только на клиенте.

Текстовое поле проектируется так, чтобы голос подключился как второй
источник той же строки: обработчик желания принимает `String` и не знает,
откуда он пришёл. Сетевой слой из §3.2 — та же основа.

## 10. Проверка

**Автотесты** (`KHGameTests`, к существующим 112):

| Тест | Что доказывает |
|---|---|
| `genie_menu_opens_for_owner` | ПКМ владельца открывает меню, а не пишет в чат |
| `genie_menu_rejects_stranger` | Чужой получает `not_owner`, меню не открывается |
| `genie_mode_payload_sets_mode` | Пакет ставит конкретный режим, а не следующий по кругу |
| `genie_mode_payload_rejects_stranger` | Пакет от не-владельца игнорируется |
| `genie_wish_payload_executes` | Желание через пакет идёт тем же путём, что через бумагу |
| `genie_wish_payload_rejects_distance` | Пакет с 50 блоков игнорируется |
| `genie_container_data_syncs` | 15 слотов содержат значения из personality/brain/memory |

**Что тестом не проверяется.** Вёрстка: выравнивание шкал, читаемость,
подбор цветов. Это проверяет человек в игре. Автоматически можно
подтвердить только наличие и позиции элементов разбором скриншота по
пикселям, но не качество результата.

**Текстура** генерируется `tools/texgen/gen_gui.py` в стиле существующей
панели маслопресса: ванильная 3-пиксельная рамка, спрайты пустой и полной
шкалы, три состояния кнопки.

**Локализация** — все строки через `KHTranslations` (ru + en).
